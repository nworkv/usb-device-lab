# Сохранённые события и история повторов

На вкладке «Результаты и повторы» появился постоянный список событий: фильтр
Kernel panic/Oops/BUG/санитайзеры/зависания/предупреждения/ошибки исполнителя,
страницы по 100 записей, контекст, ссылки на config/result/executor.log и повтор.
Ничего искать в текущем хвосте не нужно. Старые файлы не изменяются.

Реестр: results_dir/.research-events.sqlite3, права 0600. Фоновый поток работает
при запущенном сервере, даже если браузер закрыт. Активный, запрошенные и по одному
из последних 200 запусков обрабатываются циклически; выбранный старый запуск
получает приоритет. После остановленного сервера индекс догоняет сохранённые
журналы. В интерфейсе видны проиндексированные байты и ошибки. Отсутствие карточки
не доказывает отсутствие ошибки, если индекс отстаёт или захват неполный.

Читается непрерывный chunks.jsonl + оригинальные байты uart.raw, не хвост.
Шаблоны ищутся в первых 8192 байтах каждой строки; длинные строки ограничены.
Разорванный между chunks заголовок сохраняется в ограниченном буфере. При
уменьшении исходных файлов индекс не сбрасывается молча: выдаётся ошибка.
События получают стабильный ID по capture/source/byte offset и не дублируются
при повторном чтении или перезапуске. Реестр хранит заголовки, не полные дампы.

Связь ошибки исполнителя берётся из result.json конкретной попытки. Сообщение
хоста связывается с окнами, пересекающими интервал приёма заголовка на Pi;
это НЕ причинность и НЕ время возникновения сообщения на хосте. Несколько
окон/незавершённое окно помечаются явно. Для неоднозначного события оператор
выбирает кандидатную завершённую попытку. При отсутствии связи произвольная
попытка не подставляется; ручной повтор остаётся в прежнем блоке страницы.

Повтор через карточку записывает event_ref до начала рабочего потока. Новый
replay-source.json ссылается на исходные campaign/event. Фоновый индекс сохраняет
ссылку на UUID повтора; карточка показывает историю и replay-result.json, когда
он доступен. Контекст/историю можно скачать JSON; исходные конфигурации и журналы
скачиваются отдельно. Это не новый ZIP полного события и не автоматическая
проверка воспроизводимости. Хост после panic нужно восстановить вручную.

Обновление: остановить кампанию, дождаться анализа, завершить сервер, git pull
--ff-only, снова запустить dual_cli serve. Конфиг не меняется. SQLite — производный
индекс, оригинальные журналы остаются первичными материалами; не публикуйте
реестр/логи без проверки секретов. Родительские каталоги стенда должны быть доверенными.
