# HTML review download from the guarded UART panel

Restart the existing protected launcher after updating:

```sh
python3 -m usb_device_lab.uart_guarded_web --config examples/lab.uart.example.toml --seeds corpus/seeds/hid-keyboard.json --port 8766
python3 -m unittest discover -s tests -p 'test_uart_review_http.py' -v
```

The guarded launcher now uses a small Server/Handler extension of uart_web. Old
uart_web launch, base modules and campaign/checkpoint behavior remain unchanged.
The page gets an extra script with an evidence selector and HTML download button.
Select a campaign and one evidence UUID; UUID ordering is not chronological.
Exports are still generated by the offline exporter after stopping capture.

GET /api/review?campaign=<UUID>&evidence=evidence-<UUID> requires the same Bearer
header and existing Host/Origin checks. It reads only allowlisted JSON via the
existing artifact reader, bounds inputs, binds capture identity to the requested
campaign, and calls uart_review.render. It NEVER serves a stored arbitrary
review.html. The response is an attachment/octet-stream; no new HTML-origin
execution route. Existing output CSP and generated HTML's metadata CSP apply.
No files are created or overwritten by the endpoint. Missing exports return 404,
oversize inputs 413, malformed/incomplete/unsupported evidence 400.

The addon uses the already-entered in-memory token, no token URL/storage. It
shares the base page's token/epoch/AbortController bindings and metadata rows;
this coupling is intentional and must be retested if the base script changes.
Logout clears its selector; stale downloads are rejected after session changes.
No new launcher or standalone login flow. The downloaded HTML remains a review
of observational candidates, not confirmed bugs or host readiness. Files may
contain sensitive data; no redaction is implemented. Full input snapshot locking
and safe public deployment are not provided.

Nine tests passed locally: real HTTP extension routing with reconstructed base
server plumbing and mocked artifact-reader/renderer contracts; JS syntax plus a
Node simulated-DOM download/logout check. These are not a full real-JSON-to-HTML
HTTP integration test. The renderer itself has separate tests. Full checkout CI,
actual browser rendering and physical hardware were not run. Tests autojoin the
existing test_uart*.py runner; Node-dependent checks explicitly skip without Node.
