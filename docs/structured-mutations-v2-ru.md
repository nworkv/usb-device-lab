# Структурные мутации v2: первый из трёх блоков улучшений

В обычной кампании Mutator теперь выбирает присутствующие поля из speed,
descriptors, runtime, protocol и wire_mutator, включая листья и списки.
Новые цели: runtime payload/endpoint descriptor, интервалы, размеры чтения,
номера конфигураций/интерфейсов/альтернатив, control match, script states/echo/
capture/send и wire probability. Hex-поля получают битовые/байтовые операции,
целые — граничные значения, bool — инверсию, строки — ограниченные значения,
списки — удаление/дублирование/перестановку. Байт PID/VID/class в raw descriptors
по-прежнему может меняться как любой байт соответствующего массива.

Это расширение модели, НЕ доказательство, что каждое значение каждого поля
приемлемо физическому UDC или будет запрошено хостом. Каждая попытка изменения
проверяется существующим DeviceConfig/topology, до 16 вариантов на выбранную
цель; невозможное изменение записывается status=skipped с причиной. Например,
единственную обязательную runtime alternative 0 нельзя переименовать без
добавления другой alternative 0. Служебные schema_version, UDC binding, metadata
и protocol.name (выбор исполняемого plugin) не мутируются. Пути/SSH ключи здесь
вообще не являются device data. Неподдерживаемый тип runtime transfer не включается.

Для runtime endpoint предлагаются адрес, bulk/interrupt type, MPS и interval,
а обязательные байты API 7/5 сохраняются. При смене full/high speed MPS runtime
endpoints приводятся к допустимым текущей моделью размерам; зависимые изменения
перечисляются в dependent_changes. Это НЕ общий согласованный пересчёт всех
host descriptors и class-specific ссылок. Отдельный полноценный coherent mode
и аппаратные EPS_INFO проверки ещё не реализованы этим коммитом. Объявленные
host descriptors могут намеренно расходиться с runtime topology.

Trace в started.json содержит path (JSON-pointer), operation, offset для байтов,
SHA-256 до/после, accepted/skipped, версию алгоритма и причины. Значения больших
payload не дублируются в trace; оригинальная итоговая конфигурация в config.json.
Принятое изменение списка/правила не гарантирует наблюдаемого эффекта на хосте.
Mutator.catalogue(parent) показывает цели и исключения; это не страница покрытия
на сайте и не покрытие кода ядра. Времени на повторные model-validation может
стать больше: ускорение относится к третьему блоку и требует замеров.

WireMutator сохранён без изменения алгоритма. Новый wire_seed записывается в
trace; probability сохраняется, если уже задана, иначе default 0.05. Повтор
сохранённого JSON не генерирует новую мутацию. Только random.Random state влияет
на выбор; восстановление v2 PRNG воспроизводит следующий результат.

Checkpoint tag изменён на usb-tree-model-valid-v2-round-robin: старый v1 PRNG
checkpoint нельзя молча продолжить новым алгоритмом, в том числе после lease-only
миграции. Завершите старую кампанию на прежней версии либо начните новую v2.
Старые журналы/события и отдельный повтор сохранённой конфигурации остаются.
Legacy dashboard engine hash уже включает изменяемый mutator.py и также меняется.

9 новых tests прошли локально с настоящими model/topology/checkpoint исходниками,
их base Git blobs проверены; сети/USB и полного checkout regression/CI не было.
Корпус 32/512 и ускорение ещё не добавлены: это следующие два коммита, не свойства
этого первого блока. Проверка: python -m unittest discover -s tests -p
"test_dual_structured_mutator.py" -v. Новое имя входит в существующий dual CI pattern.
