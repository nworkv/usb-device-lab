# Batch: продолжение после ошибок групп

Изменено поведение batch_campaign.run_batch: kernel-кандидаты больше не вызывают review_required+break; ошибки pipeline, execution_error, analysis_error, неполные результаты и некорректный анализ записываются в строку группы, затем обход переходит к следующей группе.

progress.json содержит failed_groups, processed_groups, kernel_candidate_count, review_required и groups[].error/campaign_id. Неизвестный анализ остаётся ошибкой с kernel_candidate_count=null, а не нулём находок. completed означает конец обхода, а не отсутствие ошибок. CLI после полного обхода возвращает 1 при failed_groups>0; это не прерывает обход. Stop/SIGINT/SIGTERM сохраняют остановку.

Пределы: это продолжение между группами batch, не переписывание обычной dual_cli run. Ошибочная группа может не выполнить оставшиеся seeds; её частичный результат явно сохраняется. Повторное подключение, восстановление зависшего хоста, batch resume и параллельный replay не добавлены. UDC cleanup-marker и preflight не обходятся: следующая группа может также получить отказ и быть записана ошибочной. Ошибки общего журнала/lock/плана по-прежнему останавливают batch: продолжение без достоверной фиксации не обещается. Интерфейс пока отображает существующие состояния строк; новые поля доступны в progress.json/API, старый поясняющий текст панели ещё не обновлён.

Проверка: 6 изолированных unittest прошли с реальными временными файлами progress/plan и lock. Проверены находка, execution/analysis errors, исключение pipeline, неполный анализ, частичная группа и операторский Stop. Импорты зависимостей заменены; реальный pipeline/USB не запускался. Первый запуск harness не состоялся из-за отсутствующего импорта patch; после исправления выполнены все проверки.

Пропущены: полный checkout suite, существующие тесты прежней политики остановки, реальная панель, UART/SSH, USB hardware. Старые тесты, ожидающие остановку на finding/group error, требуют обновления под новую политику. Этот коммит не означает реализацию неограниченного восстановления при любой аппаратной ошибке.
