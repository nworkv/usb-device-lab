# Исследовательская панель: журналы и повторы

Обновление: остановить кампанию, дождаться анализа, завершить сервер; git pull
--ff-only и снова запустить dual_cli serve. Установщик/конфиг менять не нужно.
Панель использует loopback, Bearer token и SSH-туннель, как раньше.

Вкладки: Запуск, Журналы, Результаты и повторы, Архив. Токен хранится только
в памяти страницы; навигация не требует нового входа, перезагрузка страницы —
требует. Обновление каждые 2 секунды; пауза журнала не останавливает кампанию.
При выделении текста автоматическая перерисовка журнала пропускается.

Окно журнала ограничено 64 KiB по умолчанию, до 1000 строк. Поиск и счётчики
относятся только к окну. Красный — критический текстовый/priority маркер,
жёлтый — предупреждение; это эвристика, не подтверждённая уязвимость.
Фрагмент JSON выгружает именно показанное окно с фильтрами и SHA-256 исходных
байтов. Отдельно выдаются оригинальные байты окна или весь файл потоковым API.
Браузерный download Blob больших файлов может потребовать память.

Повтор: выбрать запуск и попытку, подтвердить восстановление хоста. Для старой
попытки вне последних 100 можно указать attempt-000123 вручную. Исполняется одна
сохранённая конфигурация/wire_seed без новой мутации; USB-транзакции не записаны,
поэтому одинаковый эффект не гарантирован. Текущий канал/quiet-окна фиксируются,
длительность берётся из источника. Новый UUID и файлы replay-source/result сохраняют
связь с источником, старые материалы не перезаписываются. Новый захват автоматически
выбирается один раз; затем пользователь может вернуться к источнику.
Сравнение счётчиков в backend ограничено хвостами 64 KiB двух захватов, не всей
историей и не обязательно исходной попыткой. confirmed_reproduction=False означает
«не подтверждено автоматически», а не доказательство отсутствия повтора ошибки.

ZIP разрешённых доступных материалов + манифест SHA-256: только после остановки
и анализа, до 128 MiB/4096 записей, снимок не атомарный. Недостающие файлы перечислены.
Для крупного журнала используйте отдельную выдачу файла/диапазона. Оригиналы могут
содержать секреты; автоматической редакции секретов нет.

Проверки: ранее 9 изолированных API-тестов прошли с файлами и loopback HTTP;
для подготовки повтора DeviceConfig был fixture. Новый JS прошёл node --check;
5 дополнительных тестов прошли изолированно: assets/guard, preview и JS-контракты;
HTTP-мост backend был fixture с прежним guard, исходник preview совпал с Git blob.
Это не прогон всего опубликованного API совместно с браузером.
Полный checkout CI, настоящий браузер и физический USB replay здесь не проверены.
