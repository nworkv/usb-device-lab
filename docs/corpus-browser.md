# Раздел «Корпус»

```sh
python -m usb_device_lab.dashboard serve --config lab.toml --port 8765
```

Откройте «Корпус», введите токен и выберите источник:

- seeds: исходные файлы, выбранные через corpus.families/profiles в lab.toml;
- learned: записи таблицы corpus в runs.sqlite3 и соответствующие JSON в
  results_dir/corpus. Этот индекс включает внесённые seeds, не только мутации.

Карточки показывают family/profile из metadata, описание, число дескрипторов,
конфигураций, интерфейсов и runtime-endpoints. Неизвестные поля не угадываются по
имени файла. Подробный просмотр содержит digest, speed, UDC, счётчики и полный JSON.
valid означает принятие DeviceConfig, не успешную эмуляцию или соответствие USB
на проводе. Счётчики интерфейсов суммируются по runtime-конфигурациям, endpoints —
по всем альтернативам, не только активным. Просмотр не меняет файлы, не создаёт
Store и не запускает устройства.

API защищён прежним bearer-токеном и Host/Origin:

- GET /api/corpus?source=seeds&offset=0&family=hid&profile=keyboard
- GET /api/corpus/<seeds|learned>/<64-hex-id>

Seed ID — SHA-256 имени файла, это не digest конфигурации; digest показан отдельно.
Для learned ID совпадает с digest индекса и проверяется по canonical() DeviceConfig.
Непроиндексированный JSON не открывается. Фильтры family/profile сравниваются точно.
За запрос разбирается до 200 записей, возвращается до 50 карточек. next_offset
учитывает все просмотренные записи, включая не совпавшие с фильтром; more может
быть true даже при пустом items. Используйте «Следующая порция». Исходный выбор
seed-файлов проверяется select_seeds; чтение доверенного manifest не ограничено
этим лимитом. Во время изменения индекса страницы не являются единым snapshot.

Каждый JSON ограничен 256 КиБ. Чтение через directory fd/O_NOFOLLOW не следует
симлинкам файлов и learned-каталога corpus; O_NONBLOCK предотвращает блокировку
на FIFO, затем проверяется регулярный тип. Настроенные seed_dir/results_dir
считаются доверенными корнями. Не принимаются пользовательские пути. Некорректные
файлы отображаются недоступными карточками, без раскрытия внутренних путей;
подробный JSON показывается только для принятой конфигурации. NaN/Infinity и
переполнение чисел вида 1e999 отвергаются. Список learned читает SQLite в mode=ro;
отсутствие БД означает пустой список и не создаёт БД.

HTML/JS публичны, но данные требуют авторизации. Токен не сохраняется в браузере
или URL; вывод использует textContent. Новая страница использует имеющуюся тему.

16 целевых тестов прошли при подготовке: реальные файлы/SQLite/HTTP, пагинация,
фильтры, индекс/digest, лимиты, симлинк/FIFO, числовое переполнение, авторизация и
синтаксис JS в Node.js. DeviceConfig/topology, manifest selection и базовый HTTP
сервер были подставными; реальная интеграция DashboardServer, полный набор тестов,
браузерный визуальный прогон и физический стенд не проверены. Node.js-тест может
быть пропущен при отсутствии Node.js.
