# UART-профиль: первый этап

Ветка разработки: feature/uart-agentless. Этот этап добавляет только строгую
конфигурацию, пример и отдельную команду проверки. Приёмник, UART-кампания,
проверки оборудования и подключение к dashboard пока НЕ реализованы.

```sh
python3 -m usb_device_lab.uart_config --config examples/lab.uart.example.toml
python3 -m unittest discover -s tests -p 'test_uart_config.py' -v
```

Нужен Python 3.11+. configuration_valid=true означает только корректность
формата. hardware_checked=false и runtime_connected=false указывают, что
порт не открывался и оборудование не проверялось. Загрузчик не создаёт каталоги,
не открывает UART и не запускает subprocess/SSH/агента/коллектор.

Допустимы ровно шесть секций: gadget, telemetry, uart, corpus, campaign, run.
[host] и SSH-поля отвергаются. telemetry.mode=uart; schema_version=1.
Первый профиль предусматривает strategy=round-robin и feedback=none: это не
KCOV-покрытие и не подстановка фиктивных PC из логов. Планируемое применение
этих параметров будет подключено следующим этапом.

uart.port — точный абсолютный путь в /dev; пример /dev/ttyUSB0 необходимо
заменить на адаптер вашей Pi. Для стабильного имени можно указать
/dev/serial/by-id/<имя_адаптера>. Порт не проверяется на существование, скорость
и электрические уровни — на совместимость с оборудованием. Значения примера
115200/8/none/1 — настройки формата, а не определение параметров вашего хоста.
read_timeout, reconnect_delay и read_chunk_bytes предназначены будущему читателю.
pre_run_quiet_seconds/post_run_capture_seconds предназначены будущим окнам
привязки журналов; эти задержки пока не выполняются.

Пути файлов и каталогов разрешаются относительно TOML. Пример находится в
examples и использует ../corpus, ../var. Если копируете его в корень репозитория,
замените эти пути на corpus/..., var/...; иначе они будут указывать не туда.
Каталоги исходных файлов, подготовленного корпуса, результатов и логов должны
различаться. UART-данные предлагается хранить отдельно в var/*-uart, не смешивая
с прежними SSH/KCOV-кампаниями и checkpoint. Перенос старых checkpoint не реализован.

Существующий lab.load/dashboard пока не принимает этот UART-профиль: в нём нет
обязательной для старого загрузчика секции host. Не запускайте dashboard/fuzz с
этим файлом до подключения нового backend. Старая SSH-логика не изменена и не
превращается в UART-режим автоматически. Отсутствие host предотвращает скрытый
fallback при попытке прочитать новый профиль старым загрузчиком.

14 целевых тестов прошли на реальном коде загрузчика в изолированном Python-пакете,
без заглушки UARTConfig. Проверены типы, диапазоны, неизвестные поля, запрет host,
ограничение 64 КиБ, CLI, отсутствие device/process-вызовов и неизменяемость настроек.
Полный checkout/CI, реальные UART-порты и физический стенд не проверены.
main и feature/kernel-triage этим коммитом не изменяются.
