# Список логов и ограниченный хвост

После применения изменений запустите прежний общий dashboard:

```sh
python -m usb_device_lab.dashboard serve --config lab.toml --port 8765
```

Откройте раздел «Логи», введите токен и 32-символьный идентификатор запуска
из раздела «Результаты». Список показывает executor.log, agent.log и
kmsg.delta.log с доступностью и размером. Выберите источник и число строк,
обновите хвост либо включите обновление раз в 2 секунды. Снимите флажок для паузы.
Токен не хранится в браузере и не передаётся в URL.

API:

- GET /api/logs/<run>: список фиксированных источников.
- GET /api/logs/<run>/<executor|agent|kernel>?lines=200: последние строки.

Оба API требуют bearer-токен и прежние проверки Host/Origin. HTML и JS публичны,
но не содержат содержимого логов. Допускается 1..1000 строк, максимум чтения
65536 байт. Даже одна длинная строка не снимает лимит байтов. Ответ сообщает
bytes_read, lines_returned, truncated, partial_first_line_possible и
changed_during_read. При попадании в середину UTF-8 символа применяется замена;
первая строка может быть неполной, что явно обозначается. Это снимок хвоста,
не гарантия неизменности файла во время записи и не stream с курсором.

Чтение Linux-файлов выполняется через directory fd и O_NOFOLLOW для runs,
каталога запуска и файла. Источники перечислены в allowlist; произвольные пути
не принимаются. При открытии файла используется O_NONBLOCK, затем проверяется
тип: FIFO, устройства и прочие нерегулярные файлы отвергаются. Корень results_dir
считается доверенной конфигурацией администратора. Симлинки ниже него не следуются.
Отсутствие/недоступность файла даёт 404 при запросе хвоста; список показывает
недоступный источник. Неожиданные ошибки чтения дают 503. Некорректный запрос
или нерегулярный файл дают 400.

kernel означает сохранённый kmsg.delta.log, а не прямое подключение к /dev/kmsg
удалённого хоста. executor/agent доступны по мере записи локальных файлов.
Этот коммит не изменяет agent/runner или время сохранения kernel log. Реальный
лог может содержать чувствительные сведения; автоматическое удаление секретов
из текста не реализовано. Доступ к токену должен оставаться у доверенного оператора.

```sh
python -m unittest discover -s tests -p 'test_log_*.py'
```

17 целевых тестов прошли при подготовке: 12 файловых и 5 HTTP/JS-тестов.
Использованы реальные Linux-файлы, симлинки, FIFO, HTTP и Node.js. HTTP базовый
сервер изолирован, полноценный DashboardServer/lifecycle не проверен. Синтаксис
JS проверен; выполнение UI в браузере, полный набор тестов, SSH, KCOV и физический
стенд не проверены. Node.js-тест пропускается при отсутствии Node.js.

База подготовки: feature/kernel-triage, c3f91907d0c2099154f2e5a8741d81e66eb4de38.
Контекст изменений dashboard прочитан из коммита этой ветки. Для установки
используйте либо полный patch, либо файлы ZIP вместе с dashboard-integration.patch;
не применяйте оба варианта поверх друг друга. Полный patch на реальном checkout
репозитория здесь не прогонялся.
