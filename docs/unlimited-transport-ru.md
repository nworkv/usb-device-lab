# SSH/UART без общего таймера канала и продолжение после exit 124

Причина: старый SSH wrapper запускал timeout на lease_seconds (600 s по умолчанию).
GNU timeout возвращает 124 при истечении лимита. Это инфраструктурный таймер, не
доказательство panic/Oops/BUG. Нулевой duration отключает timer.

Новые конфиги/SSHSettings/dual_init/пример используют ssh.lease_seconds=0. Явное
положительное значение 30..3600 по-прежнему означает намеренный конечный lease.
Существующий TOML автоматически не переписывается. После обновления один раз
поставьте в существующей секции [ssh]:

```toml
lease_seconds = 0
```

Остановите кампанию, дождитесь анализа, завершите сервер. Обновите ветку git pull
--ff-only, измените только lease, перезапустите dual_cli serve. Не изменяйте бюджет,
seed, корпус, UDC/driver, target/ключи или тайминги попыток ради старого checkpoint.

«Продолжить выбранную» теперь принимает прежний SSH checkpoint при переходе
положительный legacy lease -> 0. Совместимость проверяется по полному прежнему
fingerprint: меняется только lease. PRNG/прогресс/версия/остальные проверки берутся
из прежнего строгого checkpoint loader. Старый файл не переписывается. Новый
capture получает новый UUID и checkpoint с текущим fingerprint; метаданные
содержат ssh_lifetime_migrated_from. Завершённый prefix не повторяется, неуспешная
текущая попытка может повториться. Произвольные несовместимые checkpoints не принимаются.

Проверка после редактирования:

```sh
sudo -- "$HOME/usb-device-lab/.venv-uart/bin/python" -m usb_device_lab.dual_cli   --config "$HOME/.config/usb-device-lab/lab.dual.toml" --mode ssh check
```

Запуск панели прежний. Если текущая кампания имела 10000 итераций, продолжайте
её с тем же бюджетом; не начинайте новую вместо resume, если нужен прежний прогресс.

UART уже не имел общего таймера захвата и работает до stop/error. Значение
read_timeout — время одного ожидания чтения, seconds — окно одной USB попытки,
а не ограничение общей сессии. Бюджет iterations 1..10000 остаётся отдельным
условием завершения. Это не бесконечное число попыток.

Без искусственного срока жизни не означает неуязвимость к сетевому разрыву,
panic хоста, дисковым ошибкам/нехватке места или таймерам SSH server policy.
ConnectTimeout/ServerAlive, local terminate/reap и UDC cleanup marker сохранены.
При реальном разрыве новые USB попытки останавливаются: проверьте/восстановите
хост и используйте resume. Автоматического игнорирования потери наблюдения нет.
Удалённый cleanup на EOF/сигналах best-effort, после зависания проверьте процессы.

8 новых isolated tests прошли: defaults/validation, timeout 0 в команде,
строгая lease-only миграция 30/600/3600 и сохранение прогресса, отклонение другого
бюджета/target/parents, повреждённый checkpoint, код 124 и локальный fixed shell
wrapper с настоящим GNU timeout и fake dmesg/чистым stop. Старые parser/journal/
checkpoint зависимости для isolated run — fixtures; это не полный checkout suite.
Нет прогона на несколько часов, настоящего SSH server, физического UART/USB и CI.
