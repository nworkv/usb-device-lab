# USB Device Lab

USB Device Lab is a Linux USB host-stack testing lab. A gadget-side executor emulates USB devices through Raw Gadget; a host-side agent collects remote KCOV coverage and kernel logs; the runner stores every invocation, coverage result and finding.

**Status.** Every module is covered by unit tests with fake Raw Gadget, SSH, agent and collector. The end-to-end hardware loop (Raspberry Pi 4 gadget, real KCOV host) has not yet been validated on hardware; treat the first campaigns as experiments.

## Layout

- `usb_device_lab/lab.py`: `lab.toml` loader and the main CLI (`init`, `check`, `fuzz`, `replay`)
- `usb_device_lab/`: executor (`device.py`), runner, protocol, mutator, host agent, doctor and storage
- `corpus/manifest.toml`, `corpus/seeds/`: 19 starting device profiles (`<family>-<profile>.json`), regenerated by `scripts/gen_seeds.py`
- `examples/`: device and lab configuration examples
- `var/corpus/`: prepared seeds (UDC substituted from `lab.toml`)
- `var/results/`: campaign database, corpus by coverage and one directory per run
- `var/logs/`: host `dmesg` snapshots and replay inputs

## Prerequisites

- Gadget machine (e.g. Raspberry Pi 4): Python 3.11+, `CONFIG_USB_RAW_GADGET`, `/dev/raw-gadget`, a UDC. On a Pi 4 add `dtoverlay=dwc2,dr_mode=peripheral` to `config.txt`, load `dwc2` and `raw_gadget`, and use the USB-C port (UDC `fe980000.usb`) as the data link.
- Host under test: Linux with `CONFIG_KCOV=y`, `CONFIG_KCOV_INSTRUMENT_ALL=y`, `CONFIG_DEBUG_FS=y`, this repository cloned to `/opt/usb-device-lab` (or `host.remote_dir`) with `make` run there to build `build/kcov-remote`.
- Key-based SSH from the gadget to the host (`BatchMode=yes` is enforced). For a non-root `ssh_user`, allow passwordless `sudo -n` for the agent, `pkill` and `dmesg`.

## Quick start

```bash
git clone https://github.com/nworkv/usb-device-lab
cd usb-device-lab

# 1. Write lab.toml and create var/ directories
python -m usb_device_lab.lab init --host 192.168.1.20 --udc fe980000.usb --bus 1 --ssh-user root

# 2. Check everything before a campaign: Raw Gadget, UDC, Pi 4 DWC2/USB-C/kernel option,
#    corpus, SSH, remote debugfs/KCOV/kmsg and the remote collector
python -m usb_device_lab.lab check --config lab.toml

# 3. Run the campaign
sudo python -m usb_device_lab.lab fuzz --config lab.toml

# 4. Replay one input (a seed, or a run directory from var/results/runs/<id>)
sudo python -m usb_device_lab.lab replay --config lab.toml --input var/results/runs/<id>

# Results dashboard on 127.0.0.1:8080
python -m usb_device_lab web --output var/results
```

`check` prints one `OK`/`FAIL` line per item and ends with `READY` or `NOT READY`; add `--json` for the full report or `--local-only` to skip SSH. `fuzz` runs the same checks and refuses to start when anything fails (`--skip-checks` overrides). `--iterations`, `--seconds` and `--seed` override `[campaign]`.

## What `fuzz` does on the host

1. Over SSH as `host.ssh_user@host.address`: kills stale agents/collectors for `host.usb_bus` and saves a `dmesg` snapshot to `var/logs/`.
2. For every run, starts `usb_device_lab.host_agent --bus <usb_bus> --collector <remote_dir>/build/kcov-remote` over SSH. The agent starts the KCOV collector and the `/dev/kmsg` reader on `start` and stops both on `stop`, after the gadget executor has finished.
3. At the end (also on Ctrl+C or error) cleans up again and saves a final `dmesg` snapshot.

## lab.toml

See `examples/lab.example.toml` for every key. Paths are relative to `lab.toml`.

| Section | Keys |
|---|---|
| `[gadget]` | `udc`, `udc_driver` (default = `udc`), `device_config` (default `replay` input), `profile = "raspberry-pi-4"` enables Pi 4 checks |
| `[host]` | `address` (IP), `ssh_user`, `ssh_port`, `usb_bus`, `remote_dir`, `python`, `collector`, `sudo`, `ssh_options` |
| `[corpus]` | `seed_dir`, `manifest`, `strategy`, optional `families = ["hid"]` / `profiles = ["hid/mouse", "acm"]` |
| `[campaign]` | `iterations`, `seconds`, `seed` |
| `[run]` | `corpus_out`, `results_dir`, `logs_dir` |

## Seed corpus

| Family | Profiles |
|---|---|
| hid | keyboard, mouse, consumer-control, gamepad, multi-report |
| audio | uac1-playback, uac1-capture, uac1-duplex |
| cdc | acm, ecm |
| storage | bulk-only (BOT, CSW replies) |
| midi | midi-streaming |
| uvc | streaming |
| composite | hid-cdc, hid-audio, hid-storage |
| boundary | multi-config, multi-altsetting, endpoint-matrix |

Audio and UVC streaming endpoints are isochronous: they are declared in the descriptors so the host driver enumerates and probes them, but the Raw Gadget backend only executes bulk/interrupt endpoints, so no streaming data flows.

## Low-level commands

```bash
python -m usb_device_lab validate corpus/seeds/hid-keyboard.json
python -m usb_device_lab.doctor rpi4 --udc fe980000.usb
python -m usb_device_lab.doctor host --bus 1      # on the host
python3 scripts/gen_seeds.py                       # regenerate corpus/seeds
make test
```

## Safety

Run only against hosts and USB controllers you own or are authorized to test. Start with a dedicated host, a short time limit and a small seed subset (`families = ["hid"]`). Re-run `check` after every kernel, cabling or UDC change.
